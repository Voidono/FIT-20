# FIT Runner (starter) - Godot 4.4, GDScript only

Baseline for the **FIT Runner** minigame in *FIT: THE TIME STONE*. Hold to push, release to recover. One input feeds one
effort value (0-1); pace, stamina, the par ghost and the HUD all hang off it. Landscape 16:9 on a 640x360 canvas,
Vietnamese + English. **The world, the character and the HUD are scenes with swappable art**, not code-drawn shapes.

## Read this first
- **Nobody has run this in Godot.** I built it where there is no Godot. The stamina model was checked in a Python mirror and the
  scripts and scenes were cross-checked mechanically (every script reference, node name, export and signal resolves), but the
  `.tscn` files were generated by a script, not saved by the editor. Open the project in 4.4, look at the Output panel, and
  send me the first error. Open each scene once and press Ctrl+S: the editor rewrites it in its own format.
- First open imports the PNGs, the font and `i18n/strings.csv` (it creates `strings.vi.translation` and `strings.en.translation`).
  If labels show raw keys such as `ZONE_RECOVER`, check Project Settings > Localization > Translations lists both files, then restart the editor once.

## Run
1. Godot 4.4 -> Import -> `project.godot` -> F5. `scenes/main.tscn` is a stand-in for the main game.
2. Hold **Space** / **left mouse** / **touch anywhere**. **Esc / P** pauses. **F1** or the **DBG** button opens the tuning overlay.
3. Phones: keep *Input Devices > Pointing > Emulate Mouse From Touch* on (default). A tap arrives as a left click.

## Scene tree
```
scenes/fit_runner.tscn
FitRunner (Node2D)                  run_finished(result), quit_requested
+- SkyLayer (CanvasLayer -10)       Sky (TextureRect)
+- Background (Node2D)              FarHills, NearHills (Parallax2D + Sprite2D)
+- Camera (Camera2D)
+- Course (scenes/course)           Ground (Polygon2D), Track + LaneLine (Line2D), Posts, Props
|                                    Props = prop scenes you place with track_fraction: sign_flag, water_station, finish_arch
+- Ghost, Runner                    two instances of scenes/character/runner_character.tscn (AnimatedSprite2D + particles)
+- Hud (scenes/ui/hud.tscn)         instances stamina_bar, effort_gauge, progress_strip, ready_overlay, pause_menu, result_panel, rotate_overlay
+- DebugOverlay (scenes/debug)      one TuningSlider instance per number
```
Signals are connected in the scene files (Node dock > Signals), `%Name` unique nodes are used instead of long paths, and zone
looks are `ZoneStyle` nodes under `Hud/Root/Zones`. The terrain is built once per run, never per frame.

## Swapping in your art
See `assets/README.md` for every slot with sizes. Short version:
- **Character**: replace `assets/character/runner_sheet.png` (6x6 cells of 32x48, animations idle/jog/run/push/sprint/stumble/drink)
  or edit `runner_frames.tres` in the SpriteFrames panel. Different animation names are exports on `RunnerCharacter`.
- **UI**: `assets/ui/fit_theme.tres` skins buttons and panels; the bars, gauge and strip are TextureProgressBar/TextureRect nodes
  with textures you set in the Inspector.
- **World**: sky, hills (Parallax2D), grass and track tiles, props. Add props by instancing a prop scene under `Course/Props`.
- **Logo**: overwrite `assets/branding/fit_logo.png`. **Font**: `default_font` in the theme. **Text**: `i18n/strings.csv`.

## Hooking it into the main game
```gdscript
var game := preload("res://scenes/fit_runner.tscn").instantiate() as FitRunner
add_child(game)
game.run_finished.connect(func(r: RunResult) -> void:
    if r.passed: award_time_stone(1)           # r.stars, r.time_sec, r.walls_hit, r.attempt, r.par_time
)
game.quit_requested.connect(go_back)           # the main game owns scene changes
game.start({"attempt": 1, "assist": 0})        # optional; _ready() already starts a run
```
`push` is registered in code if missing, so merging needs no Project Settings changes. The minigame has its own `Camera2D`
(made current in `_ready`); when you leave it, make the main game's camera current again. Copy `main.gd`'s `_update_scale()`
if the main game does not already scale (canvas_items + keep, 640x360 up to about 18.4:9). Merge `gui/theme/custom` and the
two translation entries from `project.godot` into the main game's settings.

## Tuning
Everything is in `scripts/sim/runner_tuning.gd` (a Resource, grouped in the Inspector). Assign a `.tres` to `FitRunner.tuning`,
or use the overlay: sliders change live values; track length, mode and presets restart the run so par is rebuilt. **Copy log** puts
a CSV of effort/stamina/pace every 0.5 s plus all tuning values on the clipboard (check it in the itch.io build on an iPhone).
Add a slider by instancing `scenes/debug/tuning_slider.tscn` under the overlay's `Sliders` node and filling in its exports.

## The two input schemes (open question A vs B)
Both only produce `effort`. Switch live in the overlay.
- **A hold/release**: effort rises while held, falls on release (never below a slow jog), and moves slowly inside the cruise band so
  feathering sticks. The band is stickier early and less so later.
- **B tiers**: hold 0.55 s to climb a tier (0.30 / 0.60 / 0.80 / 1.00), let go 0.50 s to drop one. Short taps leave the tier alone.
- A third scheme (alternating taps): subclass `EffortInput`, add it to `EffortFactory`. Nothing else changes.

## Defaults I applied (the ones you approved)
- Water: **let go inside the zone** to take the cup (+15 stamina, 1.6 s slowdown). Keep holding to skip.
- Wall: at 0 stamina pace is capped at 45% until stamina is back to 35. While walled, **holding stops recovery**; let go to recover.
- Drain is a **smooth curve** through your four tier numbers (anchors at pace 0.25 / 0.60 / 0.80 / 0.95), not four steps.
- Hills change ground speed for free; uphill also drains more. Final spurt (last 15%): pace cap 1.12, drain x0.6.
- Par and ghost come from a **par bot** that plays the same model with the same input scheme. 1 star = finish before par x1.5,
  2 stars = par x1.25, 3 stars = par x1.05. Two walls quietly cut drain 10%.
- HUD: zones by colour + pattern + icon + name, effort gauge with the cruise band, "enough to finish" indicator (a copy of the model
  runs ahead at your recent average effort), +/- seconds against par, whole-course strip with elevation. Centre 60% via a 1:3:1 container.
- Auto-pause on focus loss and in portrait ("rotate your phone"). Fixed 60 Hz simulation: same run, same time, any device.

## Numbers: what the model says (`tools/strategy_sim.gd` should print the same; if it is far off, tell me)
| | A hold/release | B tiers |
|---|---|---|
| par bot = ghost | 95.4 s, 1 wall | 97.1 s, 1 wall |
| steady 0.62 effort + full spurt | 97.8 s | 106.3 s |
| mash, lets go at the wall | 123.0 s (+29%) | 121.7 s (+25%) |
| mash, never releases | 126.1 s | 126.3 s |
| cutoff (par x1.5) | 143.2 s | 145.7 s |

- **I changed two of your numbers.** Sprint drain -5 -> **-8** and wall exit 25 -> **35**. With your originals the masher is only ~6%
  slower than steady pacing in A, and in B mashing *wins* by ~6%. With the new values pacing is worth about 25%. Overlay -> **Your numbers** restores them.
- Strongest levers on time: final spurt about 5 s, water about 3 s, hill about 2 s, slope-aware effort about 1 s. Hills are the weakest lever;
  raise `uphill_*` / `downhill_*` or the hill height in `course_points` if you want them to matter.
- Even a player who never lets go at the wall still passes (126 s < 143 s). Nobody is locked out.
- Run the headless check after changing the model: `godot --headless --path . --script res://tools/strategy_sim.gd` (open the editor once first).
